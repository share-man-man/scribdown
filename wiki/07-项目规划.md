# 项目规划

更新日期：2026-10-22。

## 产品目标

Scribdown 为浏览器与 VS Code 提供一致、安全、具有手绘风格的 Markdown 阅读与预览体验。后续迭代围绕常见文档兼容性、阅读体验和内容分享展开。

本文以仓库源码与配置为现状依据。“已实现”表示已有实现，不代表本次更新重新通过全部测试或确认商店上线状态；“待实施”为建议的后续迭代，“候选”为尚未排期的方向。

各应用和共享包独立管理版本，具体版本以各自 `package.json` 和 Changesets 为准。本规划按交付阶段排序，不预先绑定版本号或日期。

## 当前缺口

| 事项         | 现状与下一步                                                                            |
| ------------ | --------------------------------------------------------------------------------------- |
| 提示块       | 尚无 GitHub Alerts 专用解析与视觉表达；优先补齐五种标准提示块                           |
| 数学公式     | 尚未接入数学语法与排版；补齐行内和块级公式，并定义错误回退行为                          |
| 打印与导出   | 尚无专用打印布局及文档导出入口；需要处理分页、宽表、长代码、图表和资源加载              |
| 阅读偏好     | 已有宽度配置与主题适配；字号、行高、字体、显式主题选择仍待补齐                          |
| 阅读位置记忆 | 已有刷新时保留阅读位置；关闭页面后重新打开同一文档的恢复能力仍待实现                    |
| 内容复用     | 表格当前复制原始 Markdown；TSV 复制、图表图片导出、章节卡片分享仍为候选                 |
| 自动化回归   | 已有单元测试与 CI；`tests/e2e` 当前仅有占位文件，Playwright 尚无实际场景，CI 未运行 E2E |
| 性能基线     | 已有高亮语法按需加载、增量 DOM 更新等优化；大文档、多图表场景尚需建立可复现的性能基线   |
| 文档一致性   | 部分说明仍沿用早期 MVP 目标或宽泛能力描述，需要随功能交付持续核对                       |

## 规划原则

- 新语法与正文交互优先落在 `packages/markdown-renderer`；视觉样式落在 `packages/ui-handdrawn`；公共常量、枚举和文案复用 `packages/shared`。
- 文件访问、偏好持久化、剪贴板权限、打印及保存入口由各宿主适配，共享包保持跨端一致。
- 新增语法保留源位置映射，避免破坏 VS Code 滚动同步、光标定位和复制原文。
- 新增公式、图表或导出能力继续遵守统一清洗策略与宿主 CSP；默认使用本地处理和随包资源。
- 功能范围、降级行为、回归样例和文档同步交付；性能问题先测量，再选择优化方案。

质量回归和性能测量贯穿各阶段，不单独等待某个功能阶段结束。

## 第一阶段：GitHub Alerts

### 范围

- 支持 `[!NOTE]`、`[!TIP]`、`[!IMPORTANT]`、`[!WARNING]`、`[!CAUTION]` 五种 GitHub 提示块语法。
- 提示块复用手绘线条、纸张与语义色 Token，提供类型标签及浅深色表现。
- 正文继续支持常规 Markdown 内容，保留原始源码与源位置。
- 首轮对齐 GitHub 语义；Obsidian 自定义标题、折叠、嵌套和扩展类型留作后续候选。

### 验收标准

- 五种类型在文档站、浏览器与 VS Code 中具有一致的正文渲染规则。
- 普通引用、代码块内标记和未知类型按约定保留，不被误转换。
- 提示类型可通过文字识别，浅深色对比度可用。
- 覆盖列表、链接、代码等内容组合；清洗、复制和源位置映射回归通过。
- fixture、支持语法说明和关键自动化用例同步更新。

## 第二阶段：数学公式

### 范围

- 优先评估现有 unified 生态中的 `remark-math` 与 `rehype-katex`，支持 `$…$` 行内公式和 `$$…$$` 块级公式。
- 数学排版脚本、样式与字体随包提供，适配浏览器扩展与 VS Code Webview 的离线和 CSP 约束。
- 明确货币符号、转义、代码块内标记及多行公式的解析边界。
- 公式错误时保留可读原文并给出局部提示；超宽公式提供横向阅读方式。

### 验收标准

- 常见上下标、分式、矩阵及多行公式在两端显示一致。
- 普通美元符号和代码内容不被误解析，非法公式不导致整篇渲染失败。
- 清洗链路保留合法公式输出，同时拒绝危险 HTML 和 URL。
- 支持读取或复制公式原文，公式块源位置映射可用。
- 核对字体资源、首屏耗时与构建体积变化，并记录新增依赖的实际成本。

## 第三阶段：打印与导出

### 交付顺序

1. 先完成打印样式：隐藏工具栏与查看器控件，定义纸张、边距、分页与浅色输出。
2. 浏览器提供打印入口，通过系统打印对话框保存 PDF；等待字体、图片、公式与 Mermaid 就绪后输出。
3. 支持带样式 HTML 导出，明确目录、代码高亮和图表的保留方式，以及外部资源的处理边界。
4. VS Code 先验证打印、文件保存及资源 URI 的可行路径，再提供对应入口；未经验证不承诺直接从 Webview 打印或保存 PDF。

### 验收标准

- 验证标题、长段落、宽表、长代码、图片、Mermaid、提示块和公式的组合文档。
- 分页尽量避免标题孤立、图表裁切和内容重叠；超出单页的元素有明确布局策略。
- PDF 保持正文可选择，文内外链接在目标格式允许时保留。
- 导出 HTML 的离线可用范围明确，远程或鉴权资源失败时有可理解的反馈，不承诺自动打包任意外部资源。
- 导出过程继续使用可信渲染结果与清洗策略，不执行文档内脚本。
- 各宿主已支持格式、保存流程与已知限制同步写入用户文档。

## 质量与性能工作

### 回归与交付

- 建立语法支持矩阵，记录支持范围、错误回退、两端差异与对应 fixture。
- 将现有 fixture 用于真实渲染器回归，优先覆盖安全清洗、主题、复制、动态更新、源位置和新语法。
- 补齐实际 E2E 场景：浏览器本地文件打开与刷新、远程 Markdown 预览、图表查看、目录与复制交互。
- 为 VS Code 建立文档切换、实时更新、滚动同步与跨文件锚点的关键路径验证；未自动化部分记录人工验收步骤。
- E2E 有稳定用例后接入 CI；现有 lint、typecheck、test、build 与各目标打包检查持续保留。
- 发布前核对 Changesets、README、文档站、商店素材和已知限制。工作流存在不等同于发布成功，制品与上线结果单独核验。

### 性能与可访问性

- 使用固定的大文档、密集代码和多 Mermaid 样例，记录输入规模、运行环境、首屏时间、更新耗时、内存与制品体积。
- 根据测量结果评估代码高亮结果缓存、图表按需渲染和后台解析，避免预先承诺 Worker 或虚拟化架构。
- 持续检查键盘访问、焦点恢复、屏幕阅读器标签、浅深色对比度与减少动态效果偏好。

UI 验收使用真实渲染预览页 `http://127.0.0.1:9174/scribdown/ui-design/render-preview`，并补充实际浏览器扩展和 VS Code 宿主验证。

## 主要风险与应对

| 风险                              | 应对方式                                               |
| --------------------------------- | ------------------------------------------------------ |
| 语法扩展影响现有内容              | 先定义解析边界，覆盖普通文本、代码和混合内容的回归样例 |
| 新节点破坏编辑器联动              | 保留 AST 源位置，验证滚动、光标定位与动态更新后的映射  |
| 公式与导出增加体积或触发 CSP 限制 | 随包资源与按需加载结合，记录制品差异，逐宿主验证       |
| 打印结果与屏幕预览不一致          | 单独设计打印布局，用代表性长文档检查分页和资源就绪状态 |
| 分享能力范围扩大                  | 先验证图表或单章节输出，再决定整篇图片、复杂模板等扩展 |
| 现状说明再次落后于实现            | 功能交付时同步能力基线、支持矩阵和用户文档             |

## 规划维护规则

- 每轮迭代开始前，从候选池收敛本轮范围与验收标准。
- 功能合入后更新状态与实现依据；版本号和发布状态以版本记录及实际发布结果为准。
- 候选方向不代表已承诺交付时间，也不作为当前产品宣传能力。
